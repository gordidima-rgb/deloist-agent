# Интерфейс на Svelte: как устроено и как добавлять

Веб-интерфейс приложения (`web/`) переезжает на Svelte 5 по шагам. Старые экраны (`index.html`, `app.js` и др.) остаются обычным JS; новые и переделанные куски пишутся компонентами Svelte и подключаются к старым страницам как маленькая библиотека. Решение владельца от 11.11.2026; те же компоненты потом можно переиспользовать с сайтом deloist.ru (тоже Svelte).

## Где что лежит

| Путь | Что это |
| --- | --- |
| `ui/src/components/*.svelte` | компоненты |
| `ui/src/lib/` | общие помощники: `i18n.js` (обёртка над `window.tr`), `mount.svelte.js` (монтирование) |
| `ui/src/index.js` | точка входа, собирает `window.DeloistUI` |
| `web/ui/kit.js`, `web/ui/kit.css` | **собранный** результат, лежит в git |
| `web/ui/.source-hash` | хэш исходников, из которых собран результат |
| `web/ui-demo.html`, `web/ui-demo.js` | витрина компонентов, только в debug-сборке |
| `tools/check_ui_built.mjs` | проверка, что `web/ui` соответствует `ui/` |

## Сборка

Нужен Node и npm, только для правок в `ui/`. `cargo build` и `cargo test` Node не требуют: собранные файлы закоммичены.

```bash
cd ui
npm ci          # один раз; версии svelte, vite и плагина закреплены точно
npm run build   # пересобирает web/ui и обновляет .source-hash
npm run dev     # то же в режиме watch
```

После правки в `ui/` обязательно `npm run build` и коммит `web/ui` вместе с исходниками. Проверка (запускай обе перед коммитом, они идут парой):

```bash
node tools/check_i18n.mjs
node tools/check_ui_built.mjs
```

`check_ui_built` считает хэш `ui/src/**`, `package.json`, `package-lock.json`, `vite.config.js`, `svelte.config.js` (переводы строк нормализуются) и сверяет с `web/ui/.source-hash`. Расхождение, пропавший `kit.js` или `kit.css` — отказ.

Новые пакеты только внутри `ui/`, с точной версией (`.npmrc` уже стоит на `save-exact`); `package-lock.json` коммитится.

## Компоненты

| Компонент | Где | Что |
| --- | --- | --- |
| `LimitRing` | витрина | кольцо доли с подписью (первый пример) |
| `Dock` | `web/dock.js` → `mountDock(#wrap)` | островок дока, места с кольцом лимита, лоток (голос, настройки, «+»), меню дока, голосовой поток; аватары монтирует `dock.js` в ячейки из `onface` |
| `StepPill` | `web/dock.js` → `mountStepPill` | плашка «чем занят бот» с девятью пикселями |
| `MicButton` | внутри `Dock`, `mountMicButton` | кнопка голоса, восемь состояний; три вида цвета (A, B, C) задаются классом на `<body>` |
| `Menu` | `web/dock.js` → `mountMenu(#chat-pop)` | меню кита по списку пунктов: «…» в шапке мини-чата; стрелки, Esc, щелчок мимо |
| `SettingsNav` | `web/app.js` → `mountSettingsNav(#settings-nav)` | разделы окна настроек на `ListItem`; стрелки ведут фокус, Enter выбирает, выбранный раздел помнит модуль (`DeloistUI.settingsNav.select/current`) |
| `kit/*` | внутри Svelte-экранов; контейнеры — `mountModal`, `mountSection`, `mountSplitView` | базовые компоненты кита: кнопки, поля, окно/шторка, разделы, списки, аватары, вкладки, пустые состояния, уведомления, раскладка. Таблица свойств — `docs/design/kit.md` |
| `KitGallery` | `/ui-demo.html` → `mountComponent(KitGallery, …)` | витрина всех базовых компонентов в двух темах (только debug) |

Стили этих компонентов — классы `.k-*` из `web/kit.css` (дизайн-кит, `docs/design/kit.md`), страница подключает его как `/kit.css`.

## Как встроено в exe

`build.rs` собирает таблицу всех файлов `web/ui/**` (кроме начинающихся с точки), `server.rs` отдаёт их по пути `/ui/<файл>`. Новый файл в `web/ui` правок Rust не требует; exe остаётся самодостаточным. Как и всё остальное, `/ui/*` закрыт сессией окна.

## Как старая страница монтирует компонент

```html
<link rel="stylesheet" href="/ui/kit.css" />
...
<script src="/i18n.js"></script>   <!-- до kit.js: компоненты зовут window.tr -->
<script src="/ui/kit.js"></script>
```

```js
const ring = window.DeloistUI.mountLimitRing(document.getElementById('slot'), { value: 0.4, color: '#22c55e', size: 56, label: 'Аня' });
ring.update({ value: 0.55 });   // перерисовка без пересоздания
ring.destroy();                 // размонтировать
```

Страница CSP-закрыта: встроенных `<script>` нет, код всегда отдельным файлом.

Новый компонент: `ui/src/components/Name.svelte`, строка `mountName` в `ui/src/index.js` (через `mountComponent(Component, target, props)`), сборка, коммит.

## Правила

1. **Перевод.** Видимый текст только через `tr('русский ключ', { vars })` из `../lib/i18n.js`. Ключ добавляется в словарь EN в `web/i18n.js`. `check_i18n.mjs` сканирует `ui/src/**/*.svelte`: ключ без перевода, `tr(\`…${x}…\`)` и русский текст вне `tr()` — ошибки.
2. **Стили через токены дизайн-кита.** Цвета, радиусы, отступы, тени берём из CSS-переменных `web/kit.css` (его готовит сессия design-kit): `color: var(--text)`, `background: var(--surface)` и т. д. Хардкод цвета допустим только как запасное значение внутри `var(--токен, запас)`, пока токен не появился. Стили компонента пишутся в `<style>` самого компонента (Svelte даёт им область видимости), общие токены в компоненте не определяем.
3. **Лёгкие.** Приложение чувствительно к CPU и памяти. Никаких бесконечных анимаций (один бесконечный спиннер однажды стоил 33 % ядра), только короткие transition, и все с `@media (prefers-reduced-motion: reduce)`. Никаких таймеров и `requestAnimationFrame` в покое.
4. **Без тяжёлых библиотек.** Не тянуть `motion` и подобные анимационные движки; не подключать иконочные пакеты целиком — только нужные SVG, вставленные в компонент. Каждый новый пакет в `ui/` обосновывать размером.
5. **Размер.** `kit.js` на одном компоненте около 14,5 КБ gzip, из них почти всё — рантайм Svelte. Следим, чтобы каждый следующий компонент добавлял килобайты, а не десятки килобайт.
6. **Доступность.** Роли и `aria-*` — как в `LimitRing` (`role="meter"`, `aria-valuenow`).
7. **Старый экран переезжает на Svelte только тогда, когда его переделывают** (редизайн). Переписывать работающий экран «ради Svelte» не нужно: это конфликты и риск без пользы.

## Витрина и проверка

В debug-сборке (`cargo run -- --server`, ссылка входа из консоли) открыть `/ui-demo.html`: там компоненты в разных состояниях. В релизной сборке этой страницы нет. Новому компоненту — строка в витрине и проверка в покое: `document.getAnimations().length === 0`, нет мутаций DOM и загрузки процессора.
